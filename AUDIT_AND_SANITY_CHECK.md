# Audit and Sanity-Check Report

## Audit scope

The original archive was reviewed across packaging, case coherence, data parsing, field typing, temporal evidence, identifiers, relationships, inject coverage, knowledge authority, starter defects, evaluation assets, participant templates, scoring, security, offline execution, reproducibility and submission controls.

## Material findings in the original package

1. The ZIP was structurally intact and all original file hashes were valid.
2. Package verification checked mainly file presence, inject count and minimum counts; it did not validate evidence relationships, fixtures, contracts, dataset profiles or clean-room repeatability.
3. The original submission checker returned success for an untouched directory scaffold.
4. The scoring table was labelled 200 points but summed to 210.
5. Public scenarios contained challenge sentences but no runnable evidence bundles, selectors, hashes, authorization context or output contracts.
6. All 32 participant templates were short generic shells, creating inconsistent artefacts and assessment ambiguity.
7. Most synthetic CSVs intentionally used a compact common evidence envelope, but the package lacked a proper dataset catalog, column dictionary, relationship rules and declared exceptions.
8. Injects referenced filenames but did not have a machine-readable evidence ledger or one-to-one test obligations.
9. The offline explorer used HTML insertion for controlled challenge values and did not provide a live result count for assistive technology.
10. Regulatory source files were link anchors only, limiting offline workshop independence.
11. There was no deterministic load-data generator, final evidence standard or submission hash utility.

## Corrections and enhancements

The v2 package adds deep validation, exact metadata, explicit exceptions, inject-specific records in referenced evidence tables, expanded authority-labelled knowledge documents, 96-inject evidence and test coverage, 18 executable fixtures, fail-closed workflow contracts, structured templates, offline regulatory guidance, safe explorer rendering, cross-platform launchers, clean submission boundaries and strict final-validation gates. No solution or expected regulated outcome was added.

## Certification method

The delivered archive is certified only after:

- immutable hash regeneration;
- two consecutive preflight runs;
- Python and JavaScript syntax checks;
- fixture and contract positive/negative tests;
- exact dataset-profile, unique-key, duplicate-row and relationship checks;
- strict empty-submission rejection;
- ZIP path-safety and duplicate-path checks;
- extraction and execution from a directory containing spaces;
- byte-for-byte comparison between source package and extracted archive.

See `VALIDATION_REPORT.json` for the machine-readable result.
