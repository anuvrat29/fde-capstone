# 12 Integration Contracts

## Purpose

APIs, events, ACORD mappings, idempotency, retries, schema evolution and reconciliation contracts for the interfaces between the three workflows and the twelve source systems in case/SOURCE_SYSTEM_FACT_PACK.md, grounded in the ACORD mapping loss, bordereaux currency, treaty-wording and event-definition injects.

## Acceptance criteria

- The artefact is evidence-led and references supplied paths, record locators and inject IDs.
- Facts, assumptions, inference, conflict, decision and residual risk are distinguishable.
- Temporal, jurisdictional, authorization and authority boundaries are explicit where relevant.
- Owners, approvals, review triggers and measurable acceptance gates are named.
- The artefact contains no unsupported coverage, pricing, reserve, payment or treaty conclusion.

## Artefact-specific acceptance criteria

- Every ACORD-mapped contract preserves effective timestamp, currency, event identifier, party role and source provenance per knowledge/ACORD_INTEGRATION_STANDARD.md; no contract silently drops a field (CTRL-IC-01).
- No bordereaux or treaty reconciliation control aggregates currency amounts without a cited FX methodology and valuation date, consistent with CTRL-DGL-02 (06_DATA_GOVERNANCE_LINEAGE.md) (CTRL-IC-02).
- Every contract with retry semantics states an idempotency key and a bounded retry count; none retries indefinitely (CTRL-IC-03).
- No integration contract in this artefact writes to PayFlow, ClaimSphere reserve fields, or ReSure treaty placement; every such edge is read/propose-only, consistent with CTRL-C4-01 (10_C4_ARCHITECTURE.md) (CTRL-IC-04).

## Required analysis and decisions

| Contract | Producer | Consumer | Schema/version | Idempotency/error rule | Reconciliation control |
|---|---|---|---|---|---|
| ACORD claim/policy event mapping | PolicyCore-IN / ClaimSphere (per case/SOURCE_SYSTEM_FACT_PACK.md) | Workflow A (evidence reconciliation) | ACORD message format per knowledge/ACORD_INTEGRATION_STANDARD.md; version pinned per integration release | Idempotency key = source message ID + endorsement effective time; on schema-validation failure, the message is quarantined and flagged, never silently dropped (directly reversing the INJ-067 failure mode) | Every mapped message is diffed against its source fields (effective time, currency, event ID, party role, provenance) before acceptance; any dropped field fails the contract test (CTRL-IC-01) |
| Bordereaux ingestion and currency-disaggregation contract | ReSure / cedent bordereaux feed | Workflow C (catastrophe/reinsurance planning) | Bordereaux schema carrying per-line currency and valuation date; no combined-currency total field permitted in the contract schema itself | Idempotency key = bordereaux batch ID + line reference; retries bounded to 3 attempts with exponential backoff, then escalate to Data Governance Owner | Reconciliation control rejects any batch presenting a pre-summed cross-currency total without a cited FX source and valuation date (CTRL-IC-02, consistent with CTRL-DGL-02) |
| Treaty wording and hours-clause resolution contract | ReSure (treaty administration) / DocVault (signed wording) | Workflow C (catastrophe/reinsurance planning) | Treaty record schema carrying wording_status (signed / slip_signed_wording_pending / other) as a mandatory field, never defaulted to `signed` | No retry semantics needed (read-only lookup); on wording_status other than `signed`, the contract returns the result labelled "provisionally interpreted — signed wording pending" | Every treaty-event response cites which of slip, signed wording, or bordereaux mapping supplied the hours-clause value used, per A-03 |
| Catastrophe event-identifier cross-reference contract | ClaimSphere (cat_events.csv-style) / ReSure (reinsurance_events.csv-style) | Workflow C (catastrophe/reinsurance planning) | Cross-reference schema carrying both the claims-side and reinsurance-side event identifiers and their respective aggregation rules, never collapsed to one canonical ID | Idempotency key = claims-side event ID + reinsurance-side event ID pair; no retry needed for read-only cross-reference lookups | Any query returning a single event ID without its paired counterpart and aggregation-rule note fails the contract test (CTRL-IC-04 adjacent; A-04) |
| Fraud-ring graph component read contract (from 08_KNOWLEDGE_GRAPH_DECISION.md / 10_C4_ARCHITECTURE.md) | Fraud-ring graph component (internal, Workflow A/C only) | Workflow A / Workflow C only, never Workflow B | Linked-evidence output schema per CTRL-KGD-03 (fields: linked entity IDs, link type, confidence, bounded-traversal-depth-reached flag); no fraud/decline/repudiation field exists in this schema | Idempotency key = query hash (input claim/party set); bounded step count enforced per REQ-NF-12 (currently unimplemented, tracked in 10_C4_ARCHITECTURE.md Open issues) | Every response is routed to a named human investigator per CTRL-KGD-03; no contract path allows an automated downstream consumer to treat the response as a fraud conclusion |

## Alternatives and trade-offs

| Option | Benefits | Risks | Cost/complexity | Reversibility | Decision and rationale |
|---|---|---|---|---|---|
| Accept the existing ACORD mapping behaviour as-is (drop endorsement effective time, currency, or event ID where the source integration already does so) | No integration rework required | Directly perpetuates the confirmed INJ-067 defect; would fail A-01 and CTRL-IC-01 outright | Lowest cost | Reversible but leaves a known defect live | Rejected. Accepting a known field-dropping defect as a design baseline contradicts the evidence-preservation principle established across every prior artefact (e.g., CTRL-OSL-02, CTRL-DDD-02). |
| Build a single generic "pass-through" contract for all twelve source systems, with no per-contract idempotency/reconciliation rule | Simpler to build once | Cannot express the source-specific defects each system carries (ACORD field loss, bordereaux currency mixing, treaty wording ambiguity, event-ID mismatch); would hide rather than surface exactly the reconciliation questions this package requires participants to make explicit | Lower initial cost, high risk of silently reproducing every confirmed defect | Costly to reverse once downstream consumers depend on the generic pass-through's (missing) guarantees | Rejected. A generic contract cannot satisfy CTRL-IC-01 through CTRL-IC-04 simultaneously, since each defect requires a distinct, source-specific reconciliation rule. |
| Five source-specific contracts (ACORD mapping, bordereaux ingestion, treaty wording resolution, event-ID cross-reference, fraud-ring graph read), each with its own idempotency key and reconciliation control | Directly addresses each confirmed/disclosed defect (INJ-067, INJ-053, INJ-051, INJ-052) with a targeted control; reuses the bounded fraud-ring component from 08/10 without inventing a new access pattern | Five contracts to maintain instead of one; requires coordination if a shared field (e.g., currency) changes format across contracts | Medium — five contracts, but each independently testable and disable-able | Reversible; any one contract can be revised without affecting the others | Selected. Matches the evidence-preservation and non-compensable-gate-1 discipline established in artefacts 01–11 without introducing a new architectural pattern beyond what 10_C4_ARCHITECTURE.md already specifies. |
